# Model artifacts

Large ONNX binaries are generated by the `ml/` training pipeline or `scripts/generate_demo_assets.py` and are gitignored.

Expected files:
- `disease_v1.onnx` — rice leaf disease classifier (MobileNetV3-Small trained on Paddy Doctor subset)
- `disease_v1.json` — class labels, input size, normalization, unknown threshold, SHA-256 hash, provenance

## Train from scratch (recommended)

```bash
cd "/home/brian/projects/subdomains/domain brian/Smart Farming"
source backend/.venv/bin/activate
pip install -r ml/requirements-export.txt

python ml/training/download_paddy_doctor.py
python ml/training/prepare_split.py
python ml/training/train_disease.py
python ml/evaluation/evaluate_disease.py
python ml/export/export_disease_onnx.py
python ml/training/copy_fixtures.py
```

See `docs/model-disease.md` for metrics and provenance.

## Generate without retraining

If `ml/checkpoints/disease_v1_best.pt` already exists locally:

```bash
python ml/export/export_disease_onnx.py
# or
python scripts/generate_demo_assets.py
```

If export fails (missing checkpoint/torch/onnx), the backend reports `model_available: false` and disease inference returns `status: unknown` with `inference_mode: unavailable`. It does **not** fall back to a color heuristic or claim a trained classification.
